# 立体库启发式算法

本轮实现文件演示：入库、出库规划接口与页面、结果展示、逐次保存和测试。远程库存及 SKU 接口留待联调；当前每次使用页面本次加载的库存快照，推荐后库存不自动作为下次输入，也不回写外部库存。

## 使用

1. 启动 `python apps/web_portal.py --host 127.0.0.1 --port 8010`。
2. 在首页算法设置中，将入库、拣货两个模块分别保存为启发式。保留原配置，不自动从 COPT/OR-Tools 切换。
3. 打开入库或出库页面，加载本次库存及订单；默认 SKU 来源为 `data/sku.xlsx`，可上传补全的 CSV/XLSX。
4. 点击开始规划，再点击查看结果。缺失规格、非法库存或超时会保存失败记录；缺货或库位不足输出可满足部分并弹窗。

SKU 文件沿用 `编码、货品名称、所属客户、托含量`，托含量为箱/托的正数。默认按所属客户与输入货主名称匹配，忽略空白和中英文括号差异；可增加 `货主编码` 明确匹配货主。名称无法对应或缺少托含量时须补全规格，不跨货主借用数据。

库存采用可用主单位数量出库，优先读取 `可用数量`，其次换算 `可用量(订单单位)`；占位及容量仍按库存总量判断。原始文件数量保存在输入记录中，计算按主单位数量及转换比进行，避免把舍入的0.167箱反算成1.002瓶。

## 规则

- 距离为通道距离＋层数差×1.7米×权重，初始权重1，可在规划页调整。通道双向，只有前通道及20—22列贯通处可跨货架；同一列各层映射到地面停靠点。
- 入库先独立存放；空位不足时尝试将新尾板追加到同货主第1层单SKU尾板，或将本次不同SKU尾板组托入第1层空位。容量采用所有参与SKU的最小托含量。已有多SKU混托不追加，混托出库后只剩一个SKU时可追加。规划不移动已有货物。
- 不足一箱优先占用第1层，其次其他尾板；整托不放第1层。高周转优先第2层，中周转偏好第2—4层，低周转优先最高层，无等级按低；偏好层不足时在合法货位中按距离退让。
- 周转按连续30天入库＋出库箱数，在各仓库内将货主＋SKU条目按量降序排序，以累计贡献80%/95%分级；跨阈值条目归入当前等级，零搬运量最低。使用最近一次手动更新的完整历史及截止日重算；尚未更新时使用样例完整历史。
- 出库默认FIFO策略：尾板优先，同组按入库时间，同时间优先距离近。先固定来源及数量，再按最近邻安排路线，FIFO不限制访问顺序。
- 出库按页面开关传入 `storeBatchFlag=0`（按单）或 `1`（整次请求作为一个波次）。按单保留订单边界，波次保留各订单缺货归属。载货只允许同一货主，切换货主先卸货。
- 同SKU可连续拣至满托；加入不同SKU后以新最小托含量检查累计箱数，拟取货量使新容量超限时先卸当前货物，恰好满载则取完再卸。最后不足一托也送出口。

## 代码入口

入出库请求、文件上传与结果读取统一在 `apps/warehouse_service.py`，共用解析与数据校验在同级 `apps/warehouse_data.py`。任务流程分别位于 `modules/slotting/planning_service.py` 与 `modules/picking_path/planning_service.py`，求解代码继续保留在 `solvers/`。目录及调用链见 [前后端分层说明](前后端分层说明.md)。

Web与远程平台使用相同的入出库POST。文件模式为默认的 `source=file_snapshot`；`source=platform` 每次从统一入口调用库存及SKU获取函数。两个远程GET目前尚未联调，会明确失败，不回退到文件数据。

## 接口及结果

- `POST /api/slotting/plan`：入库。
- `POST /api/picking-path/plan`：出库。
- 请求为JSON，包含标准化的 `inventory`、`orders` 数组及可选 `specs`、`layer_weight`，出库另有 `storeBatchFlag`。页面负责通过现有文件接口加载标准化数据；这是文件演示接口，尚非远程平台兼容协议。
- `POST /api/warehouse/specs`：上传SKU规格。
- `GET /api/warehouse/runs/{run_id}`：读取完整结果。
- `/warehouse-results/{run_id}`：独立结果页面，包括货位、层、货主、SKU、FIFO时间明细、实际通道路径、分段距离、载荷和预计库存。
- 每次保存到 `results/warehouse/{run_id}/input.json` 与 `result.json`，包含输入快照、参数、状态和结果。状态为 `feasible`（可行未证最优）、`partial`（部分满足）或 `failed`。
- `shortages` 按订单、货主、SKU提供需求、满足、缺货数量，单位为该SKU主单位；无缺货为空数组。入库 `unassigned` 保留未分配数量与原因。

启发式单线程，线程数与相对间隙不生效。时间上限用于规划循环截止检查，不包含解析及保存；超时不发布未完成方案。COPT、OR-Tools旧基线接口继续保留，但未接入本轮立体库规则。

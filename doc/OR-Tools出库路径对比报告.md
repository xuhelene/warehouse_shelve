# OR-Tools 与 VNS 出库拣货路径对比

## 测试范围

| 用例组 | 数量 | 验证重点 |
| --- | ---: | --- |
| 业务规则 | 58 | 尾板优先、FIFO、货主隔离、按单与波次、缺货、跨层和分数箱量 |
| 历史订单形状 | 255 | 保留历史订单形状的合成库存和订单 |
| 多 SKU、多托 | 72 | 2–4 个 SKU、30/60/105 箱、整托与尾板、按单与波次 |
| 小规模最优解 | 21 | 单托、4–5 个货位，用全排列独立计算最短闭合路径 |

两种算法均调用立体库出库规划入口，使用相同的库存、订单、SKU 托含量和仓库距离规则。每个用例用独立的有理数 FIFO 计算核对选货批次、数量、缺货和库存扣减，并复核每趟载量、货主隔离、按单隔离、回备货区和路线距离。VNS 继续检查历史用例指定的分托和访问顺序，OR-Tools 允许在相同业务约束内产生不同路线。

## 计时口径

Windows、AMD Ryzen 9 8945H（16 逻辑处理器）、Python 3.10.20、OR-Tools 9.14.6206。每个用例每种算法跑三次，交替先后顺序。共用每次 10 秒搜索时限。OR-Tools 配置 8 个搜索线程，VNS 单线程。计时包含选货、求解器建模、搜索与路线构造。数据准备、原生库首次加载、验收和文件写入在计时区间外。每例按三次用时的中位数取延迟，并使用对应运行的距离和趟数。各组 P95 按用例中位数的最近秩计算。

在已安装项目依赖和 pytest 的环境中，从项目根目录运行以下命令。

```powershell
python -m tools.compare_outbound_ortools --repeats 3 --time-limit 10 --threads 8
```

每例的输入、两种算法的三次结果和耗时保存在 `results/testing/outbound_ortools_*`。汇总文件 `summary.json` 包含用例组统计、逐例对比以及 OR-Tools 阶段状态。

## 多托路线差异示例

- `multi_WHCP01_2sku_105boxes_mode1_tails` 为 2 SKU、105 箱的尾板波次。VNS 的中位时延运行返回距离 471.00，OR-Tools 返回 459.45，缩短 2.45%。两者用时均约 10 秒。
- `multi_WHCP01_3sku_60boxes_mode0_tails` 为 3 SKU、60 箱的按单尾板用例。VNS 用时 0.419 秒、距离 192.45。OR-Tools 用时 0.099 秒、距离 205.10，比 VNS 长 6.57%。两者都使用 4 趟，但装载量不同。OR-Tools 在三次运行均返回 `OPTIMAL`。这个状态适用于固定拆分明细后的 CP-SAT 模型，VNS 会随拣货顺序重新计算同 SKU 的装载拆分，因此两者可搜索的方案范围不同。

## 实测结果

406 个用例全部通过，每种算法完成 1,218 次运行。路径距离按仓库模型单位统计。下表的 P50 和 P95 均以每例三次运行的中位时延为样本。

| 用例组 | VNS 总距离 | OR-Tools 总距离 | OR-Tools 更短 / 相同 / 更长 | VNS P50 / P95（ms） | OR-Tools P50 / P95（ms） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 业务规则 | 1,568.25 | 1,568.25 | 0 / 58 / 0 | 0.70 / 3.99 | 0.74 / 23.15 |
| 历史订单形状 | 18,622.00 | 18,622.00 | 0 / 255 / 0 | 0.62 / 1.54 | 0.57 / 15.58 |
| 多 SKU、多托 | 20,607.70 | 20,484.65 | 5 / 62 / 5 | 423.24 / 9,994.61 | 370.09 / 10,095.82 |
| 小规模最优解 | 3,034.65 | 3,034.65 | 0 / 21 / 0 | 9.79 / 28.01 | 27.67 / 30.48 |

整体总距离从 43,832.60 降至 43,709.55，降幅 0.28%。两者均为 629 趟。距离差异均来自多 SKU、多托组，该组 OR-Tools 总距离下降 0.60%，中位时延下降 12.56%。在 21 个小规模用例中，两种算法每次运行都达到独立枚举最优距离。

多 SKU、多托组有 22 个用例至少一次触发 OR-Tools 时限标记，VNS 为 5 个。OR-Tools 有 11 个用例至少一次回退到初始路线，分布为历史形状 3 个、多 SKU 多托 7 个、小规模最优解 1 个。时限用于搜索预算，求解器收尾和结果构造可使实测时延略超过 10 秒。部分基准用例与旧回归测试短时并行，时延数据包含这段机器负载。

本次运行的原始数据位于 [summary.json](../results/testing/outbound_ortools_20261109_090215_572574/summary.json)。另有 61 个相关 pytest 回归测试通过。

## CP-SAT 剪枝和初解提示实验

复跑命令为 `python -m tools.benchmark_outbound_cp_sat`。72 个多托用例在 1 秒和 3 秒预算下各运行一次，配置 8 个搜索线程，逐次通过独立业务校验。另选两个难例，在 10 秒预算下依次关闭两项、只开剪枝、同时开启两项，每种配置运行一次。

| 预算与配置 | 总距离 | 对历史 10 秒版更短 / 相同 / 更长 | P50 / P95 | 触发时限 |
| --- | ---: | ---: | ---: | ---: |
| 1 秒，剪枝 + 提示 | 20,589.35 | 0 / 65 / 7 | 0.342 / 1.097 秒 | 31 |
| 3 秒，剪枝 + 提示 | 20,521.45 | 0 / 70 / 2 | 0.368 / 3.082 秒 | 26 |
| 历史 10 秒版 | 20,484.65 | 基准 | 0.370 / 10.096 秒 | 22 |

与历史 10 秒版相比，1 秒、3 秒总距离分别增加 0.51%、0.18%。历史时延取三次运行的中位数，短预算结果为单次测量。

2 SKU、105 箱尾板波次的候选弧从 552 减到 456。三种配置最后都返回 459.45，在求解开始后分别用 3.736、1.439、0.424 秒找到该距离。4 SKU 对应难例的 650 条候选弧均保留，找到相同最终距离 382.30 分别用 0.658、1.339、2.912 秒。两例的建模耗时在 0.031–0.063 秒之间，六次均在约 10 秒返回 `FEASIBLE`。初解提示的效果因实例而异，这两例的最优性证明仍受下界限制。

## 3 秒预算下的初解提示复测

运行 `python -m tools.benchmark_outbound_cp_sat --compare-hints`，对同一批 72 个多托用例固定 3 秒搜索预算和 8 个线程。两组均开启剪枝，每例交替运行提示开关各三次。432 次运行均通过业务校验。总距离由各用例三次距离的中位数加总，P50/P95 以各用例三次时延的中位数计算。最差退化按任意单次运行与对应历史 10 秒版的距离比较。

| 仅容量剪枝 | 20,512.25 | 0.338 / 3.076 秒 | 4.325 秒 | 20 / 216 | +6.58% |

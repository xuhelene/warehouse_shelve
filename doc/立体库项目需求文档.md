# warehouse_shelve 立体库项目需求文档

版本：V0.1（需求讨论稿）  
日期：2026-10-12  
项目：warehouse_shelve

## 1. 项目背景与范围

在 warehouse_opt 框架基础上建设独立立体库项目，包含两个业务功能：入库货位推荐、出库拣货路径推荐。

仓库采用多层立体货架，通过人工/叉车装卸，无自动化设备。模型需要识别货架层，但不考虑设备运行相关影响，如设备调度、运行速度、升降时间、设备冲突和设备能耗。层数参与存放规则；是否参与距离计算尚待确认。

本次文档定义业务需求，不实施模型或代码修改。现有平库代码与示例数据仅作为框架基线，不视为立体库功能已经实现。装车推荐、托盘摆放及自动化设备调度不属于本项目目标功能。

## 2. 业务目标

- 入库：在满足容量及存放规则的前提下，最小化入库距离。
- 出库：在满足库存数量及出库优先规则的前提下，最小化拣货路线距离。

入库距离的起点、计量方式及数量权重，出库路线的起终点和批次范围需要确认。现阶段不擅自将两个目标合并为加权目标，也不默认用入库距离代替未来出库距离。若入库推荐也需要评估未来出库距离，应另行确认估算方法及两者优先级。

## 3. 术语与数据粒度

| 术语 | 含义 |
| --- | --- |
| 库位 | 货架某层的一个存放位置，容量为一个物理托盘 |
| 整托 | 按 SKU 的标准满托数量判定为满托的货物，数量口径待资料确认 |
| 尾板/拆零托盘 | 未满一托的货物或拆零后剩余的托盘；两种情况是否使用同一优先规则待确认 |
| 混放 | 不同 SKU 的不足一托货物允许共用存放空间；具体是同一物理托盘混 SKU，还是其他现场操作形式，待确认 |
| 周转等级 | 用于区分高周转与低周转货物的业务分类，计算指标及阈值待确认 |
| 先进先出 | 多个拆零托盘按确认后的入库/形成时间从早到晚选择 |

为表达混 SKU 和托盘级出库顺序，建议采用“库位—物理托盘—SKU/批次明细”的库存关系。此为数据结构建议，托盘编号、批次和时间字段的可获得性需确认，不直接沿用原项目“一库位一个 SKU+批次”的限制。

## 4. 已确认业务规则

| 编号 | 规则 | 类型及说明 |
| --- | --- | --- |
| BR-01 | 每个库位存放 1 托货物 | 容量上限为一个物理托盘；空库位允许存在 |
| BR-02 | 拆零后的尾板优先放在 1 层 | 优先规则；不等同于禁止放高层，1 层不足时的处理待确认 |
| BR-03 | 高周转货物优先放在 1 层，低周转货物优先放在高层 | 优先规则；等级定义、目标层及冲突处理待确认 |
| BR-04 | 不同 SKU 如果都是不足 1 托允许混放 | 允许而非强制；混放方式与容量核算待确认，不能简单将两个不足一托之和视为可装一托 |
| BR-05 | 出库优先清空拆零托盘，多个拆零托盘先进先出 | 选库存时先执行该规则，再优化路线；清空条件及 FIFO 时间口径待确认 |

单库位单托盘与混放必须同时成立。若现场混放是同一物理托盘存放多个 SKU，该托盘仍只占一个库位；若现场混放指多个独立托盘共同占一个库位，则与 BR-01 存在冲突，需要先确认。

尾板优先与低周转上高层可能冲突。例如低周转尾板同时满足两条规则，现阶段不擅自决定优先级。混托包含不同周转等级时，也需要确定整托的层级偏好。

## 5. 入库货位推荐

### 5.1 输入

- 货位布局与可用状态，包括货架、层、库位及通道关系。
- SKU 主数据及周转信息。
- 当前库存快照：库位、托盘、SKU、数量，以及能够表达 FIFO 的时间信息。
- 本次待入库货物：SKU、数量；批次、到货时间等字段按业务口径补充。
- 入库起点和经确认的距离规则。

### 5.2 流程与功能

1. 检查输入完整性、一致性和货位占用状态。
2. 按确认后的满托标准识别整托与尾板；新入库不足一托是否归入尾板待确认。
3. 识别高/低周转等级，形成层级偏好。
4. 按单库位单托盘约束筛选可用库位；混放候选按确认后的规则处理。
5. 在满足约束和优先规则的候选方案中优化入库距离。
6. 输出推荐方案、距离及未能分配的货物与原因。

### 5.3 输出

- 推荐库位、货架、层、托盘及 SKU 数量明细。
- 整托/尾板标识、周转等级；存在混放时展示各 SKU 明细。
- 推荐方案的距离统计，按确认后的口径计算。
- 无法分配、输入缺失及优先规则未满足的说明。
- 推荐后的预计库存状态，与实际库存是否同步更新另行确认。

## 6. 出库拣货路径推荐

### 6.1 输入

- 出库订单或任务：SKU、需求数量；批次限制如有应提供。
- 当前库存快照，包含物理托盘、SKU 数量、尾板状态和 FIFO 时间信息。
- 可通行通道网络、库位对应的取货停靠点、路线起终点。
- 求解器、时间限制和线程数。

### 6.2 流程与功能

1. 检查订单、库存和通道数据。
2. 根据需求选择库存，优先取拆零托盘；多个拆零托盘按 FIFO 选择。
3. 库存不足时明确报告未满足的 SKU 和数量，不能输出表面完整的方案。
4. 根据选定库存形成拣货明细，再优化访问停靠点的路线。
5. 输出路径、距离、逐库位/托盘取货量和拣货后的预计剩余库存。

“选库存的 FIFO”和“路线访问顺序”需要区分：BR-05 是否仅限制选择库存，还是同时要求实际访问顺序遵守 FIFO，待确认。不得为了缩短距离而绕过已确认的库存优先规则。

多个货架层是否共享一个通道停靠点、同一点不同层的任务如何合并展示，需根据布局和作业方式确认。模型不引入设备升降时间。

### 6.3 输出

- 拣货任务：订单/任务、SKU、托盘、库位、层、取货数量。
- 路线：起终点、停靠点访问顺序、实际通道路径和距离。
- 预计清空的拆零托盘及剩余库存明细。
- 未满足需求及原因。

## 7. 输入资料与数据准备

用户将提供货位布局图、SKU 主数据信息和主入库历史数据，资料形式为文档。应先核对资料内容，再整理为框架可读取的数据表。当前不承诺自动解析任意文档或图纸；识别出的字段、单位及对应关系需核实。

| 资料 | 需提取/核实的信息 | 用途 |
| --- | --- | --- |
| 货位布局图 | 货架、库位编码、层号、通道、入口/出口、可达关系、距离或比例尺 | 库位建模和距离计算 |
| SKU 主数据 | SKU 编码、计量单位、标准满托数量；混放容量判断需要的尺寸/重量等现场标准 | 托盘判定、数量转换和混放校验 |
| 主入库历史数据 | SKU、时间、数量、单位；批次/托盘信息如有 | 历史分析及业务口径核对 |
| 当前库存（需补充） | 库位、托盘、SKU、数量、时间、批次及可用状态 | 入库占用判断与出库选库存 |
| 出库任务（需补充） | 订单/任务、SKU、数量、批次要求如有 | 路径推荐的需求输入 |
| 出库历史或业务周转等级（需确认） | SKU 出库频率/数量、统计周期或人工等级 | 高/低周转分类 |

仅有入库历史不能自动等同于出库周转率，也不足以还原当前库存；是否允许以入库历史估算周转，需要用户确认。布局图若缺少比例尺、距离或连通信息，也不能直接得到可靠路线距离。

## 8. 框架与页面要求

沿用当前技术架构，不在需求讨论阶段新增不必要抽象：

- data/：按业务组织输入数据，支持手动选择/上传输入。
- modules/：入库与出库业务预处理、建模、服务和结果整理。
- solvers/：启发式、COPT、OR-Tools 后端；沿用项目三种方式的要求。现有拣货基线只有启发式和 OR-Tools，立体库的 COPT 后端需要后续补充，不能标记为已有能力。
- apps/：FastAPI 页面、任务调度与结果展示。
- results/：每次求解的输入记录、参数、状态、结果和距离统计按任务保存。
- doc/：需求与业务口径说明。

入库推荐和出库路径分别提供配置与结果展示页面；支持求解器选择、时间限制和线程数设置。各后端参数支持差异应如实展示。

结果页面需能区分货架层并查看库位/托盘/SKU 明细；展示路线和距离。采用分层二维图还是三维图后续确认，不默认三维是必需功能。

求解结果保存与实际库存变更分开处理；是否采用确认推荐后更新库存、外部库存导入等方式，需要确定，当前不实现自动库存回写。

## 9. 实施前待确认问题

| 编号 | 问题 | 可选理解/需确认内容 |
| --- | --- | --- |
| Q-01 | 距离如何计量？ | 水平通道实际距离；或加入层间距离。不得自行引入设备时间 |
| Q-02 | 入库距离的起点与汇总口径？ | 单/多个入库口；逐托单程距离之和或完整作业路线；入出库是否分别优化 |
| Q-03 | 出库路线范围？ | 一单一趟或波次合并；起终点相同或不同 |
| Q-04 | “优先”怎么执行？ | 在可行时严格优先，或允许以距离权衡；1 层满时可上高层还是报告无法分配 |
| Q-05 | 尾板与周转等级冲突？ | 尾板规则优先、周转规则优先或其他明确次序；混托等级如何确定 |
| Q-06 | 周转等级怎么形成？ | 人工给定；出库历史计算；经确认后使用入库历史代理。需要周期和阈值 |
| Q-07 | 满托与尾板如何判定？ | 每 SKU 固定满托数量或其他标准；本次入库不足一托是否属于尾板 |
| Q-08 | 混放的实际操作与容量限制？ | 同物理托盘混 SKU；是否合并已有尾板；哪些 SKU 可混、数量/体积/重量如何核算 |
| Q-09 | FIFO 用哪个时间？ | 原始入库时间或拆零形成时间；混托各 SKU 分别计时还是整托计时 |
| Q-10 | 清空与访问顺序规则？ | 需求小于最早尾板余量时是否可部分取；FIFO 是否限制路线访问顺序；整托的选取规则 |
| Q-11 | 库存与订单资料是否可提供？ | 当前库存、托盘编号、出库需求、周转依据；仅入库历史不够 |
| Q-12 | 作业后库存如何管理？ | 输出预计库存供外部使用，或确认执行后更新；已有库存是否允许主动移位 |

以上是待确认问题，不是默认设计。收到业务资料后，应优先澄清影响可行性和目标函数的项目，再开展实现。

## 10. 验收场景

下列验收基于已确认规则；涉及待确认项的期望结果，应在业务口径确定后补齐。

| 场景 | 验收要点 |
| --- | --- |
| 空位入库 | 推荐合法库位，不超过一托容量，层号和距离可核查 |
| 已占用库位 | 不额外放第二个物理托盘；若追加到已有混托，须符合明确混放规则 |
| 尾板入库 | 在可满足时体现 1 层优先；不足时执行确认后的处理规则 |
| 高/低周转入库 | 在可满足时体现对应层级偏好；冲突按确认后的优先级处理 |
| 不足一托的不同 SKU | 允许满足混放条件的方案，同时校验实际托盘容量；整托不能因该规则混放 |
| 多个拆零托盘出库 | 先使用拆零托盘，多个尾板按确认的 FIFO 时间选择，数量守恒 |
| 混托部分出库 | 只扣减对应 SKU 数量，不误清空其他 SKU；整托物理清空需所有货物取完 |
| 通道绕行/不可达 | 路线沿可通行网络计算；不可达时明确报告，不穿越货架 |
| 库存/容量不足 | 输出未满足数量与原因，不伪造完整可行结果 |
| 手动选择与求解参数 | 两个功能均支持输入选择和规定后端/参数；结果可追溯到输入与参数 |
| 多次求解 | 任务结果独立保存，不覆盖之前的任务 |

“最小化距离”是优化目标，不能把限时启发式或未证明最优的求解结果称为全局最优。结果应区分可行解、最优解、未找到可行解及失败，并保留后端可提供的状态信息。

# warehouse_shelve 立体库项目需求文档

版本：V0.13（需求讨论稿）
日期：2026-10-21
项目：warehouse_shelve

## 1. 项目背景与范围

武汉联众老窖城配立体库项目，包含两个业务功能：入库货位推荐、出库拣货路径推荐。

仓库采用多层立体货架，通过人工/叉车装卸，无自动化设备。模型需要识别货架层，但不考虑设备运行相关影响，如设备调度、运行速度、升降时间、设备冲突和设备能耗。层数参与存放规则和距离计算。距离采用水平通道实际距离加加权层间距离；层间距离权重可配置，先预设一个值，后续根据实际效果调整，初始数值待确认。该权重不代表设备升降时间。

## 2. 业务目标
客户需求： 城配项目出库按照先进先出原则，且存在拆零场景，需要智能调度系统优先清空尾板货物，并自动查找最早批次货物，同时满足以下要求：
- 入库：在满足容量及存放规则的前提下，最小化入库距离。
- 出库：在满足库存数量及出库优先规则的前提下，最小化拣货路线距离。

入库采用单个入库口，按逐托单程距离之和累计，不计返程；入库起点与出库起终点统一采用下述备货区。出库同时支持一单一趟和波次合并，使用接口预留参数 storeBatchFlag 表达模式，枚举已确认1为按波次、0为按单，默认值待确认；入库起点、出库起点和出库终点均视为同一备货区，位于 C14、C15 货架外 3.5 米处，区域宽度为 C14、C15 货架宽度之和；这是大致位置，不要求精确坐标。入库只考虑本次入库距离，暂不考虑未来出库成本。出库按叉车最多承载一托的完整作业路线累计距离，包含满托送至出口及继续拣货的路段。

## 3. 术语与数据粒度

| 术语   | 含义                                                 |
|------|----------------------------------------------------|
| 库位   | 货架某层的一个存放位置，容量为一个物理托盘                              |
| 整托   | 按 SKU 的标准满托数量判定为满托的货物，数量口径待客户更新确认                  |
| 尾板   | 不满一托的货物均称为尾板，包括拆零后不满一箱的货物；                         |
| 拆零托盘 | 拆零后的未满托货物，属于尾板；未拆零但不足一托的货物也属于尾板                    |
| 混放   | 不同 SKU 的不足一托货物允许混放在同一个托盘                           |
| 周转等级 | 根据近30天入库箱数＋出库箱数，将同一仓库内的货主＋SKU独立条目统一排名，分为高、中、低三级；同 SKU 不同货主分别计算 |
| 先进先出 | 多个拆零托盘按入库时间从早到晚选择                                  |

库存及出入库订单资料可提供，但没有托盘编号，托盘本身不作身份区分。采用货物—货位关系建模，不要求托盘编号，也不将每个物理托盘单独建模为决策变量；一库位一托仍作为物理容量约束。正式库存接口已确认可保留货主、货位、SKU、批次及各自入库时间的数量明细，包括同货位多 SKU、多批次以及同 SKU 不同入库时间的记录；不能汇总后丢失 FIFO 依据。混放容量暂采用参与混放 SKU 的最小托含量；独立存放及混放触发原则见5.4。

## 4. 已确认业务规则

| 编号    | 规则                        | 类型及说明                                                                   |
|-------|---------------------------|-------------------------------------------------------------------------|
| BR-01 | 每个库位存放 1 托货物              | 容量上限为一个物理托盘；空库位允许存在                                                     |
| BR-02 | 尾板优先放在 1 层                | 优先规则；不等同于禁止放高层，1 层不足时可放在高层                                              |
| BR-03 | 高周转优先第2层；中周转偏好第2—4层；低周转优先最高层 | 先满足层级偏好，再优化距离；均保留软偏好含义，尾板规则优先。中周转货量充足时可用第2层，低周转货位充足时可用低层；无周转等级默认最低等级。ABC采用近30天入库箱数＋出库箱数累计贡献80%/95%，偏好层不足按距离退让，见5.4、7.3 |
| BR-04 | 同货主的不同 SKU 如果都是不足 1 托允许混放 | 允许而非强制；暂按参与混放 SKU 的最小托含量（箱/托）限容，累计箱数不得超过该值；仅将新入库不足托货物追加到第1层已有货位，或本次多SKU组混托入第1层空货位；不搬动已有库存，见5.4 |
| BR-05 | 出库优先清空尾板，多个尾板先进先出         | FIFO 按入库时间；需求小于最早尾板余量时允许部分取，超过时先取尾板再拆零；尾板库存不足时整托也按入库时间选择；FIFO 不限制路线访问顺序 |
| BR-06 | 出库叉车每次最多承载一托              | 未满一托且仍有待拣货物时继续拣货；拣满一托送到出口，再继续剩余任务；距离按完整作业路线累计                           |
| BR-07 | 入库、出库按货主隔离 | 入库时不同货主的货物不能混放；出库时不同货主的货位不能混发。相同 SKU 也不能跨货主替代库存；订单、库存匹配及 FIFO 库存选择必须保留货主编码并限定在对应货主内 |

BR-04 的不同 SKU 尾板混放仅适用于同一货主，不允许跨货主混放。出库合拣与波次组织也必须遵守 BR-07 的货主隔离要求。

单库位单托盘与混放必须同时成立。若现场混放是同一物理托盘存放多个 SKU，该托盘仍只占一个库位；若现场混放指多个独立托盘共同占一个库位，则与 BR-01 存在冲突，需要先确认。

尾板与周转等级的冲突指入库选货位时的层级偏好冲突，例如低周转尾板既应优先放 1 层，又有放高层的偏好。已确认此时尾板规则优先。尾板按不足一托识别，包括拆零后不满一箱的货物，统一适用尾板层级偏好。第1层不足时允许上高层；第1层优先给拆零后不足一箱的货物，其次给其他不足一托货物。混托包含不同周转等级时的层级偏好仍待确认。

## 5. 入库货位推荐

### 5.1 输入

- 货位布局与可用状态，包括货架、层、库位及通道关系。
- SKU 主数据及周转信息。
- 每次调用先查询实时库存快照：库位、SKU、数量、入库时间及批次等明细；不要求托盘编号。
- 本次待入库货物：SKU、数量；批次、到货时间等字段按业务口径补充。
- 入库起点为 C14、C15 货架外 3.5 米处的备货区；距离规则：逐托累计入库口至推荐库位的单程距离，不计返程。

### 5.2 流程与功能

1. 检查输入完整性、一致性和货位占用状态；入库时优先查询远程平台最新 SKU 主数据，仍缺必要信息时停止本次推荐，并按 7.4 提示维护。
2. 按 SKU 满托标准识别整托，按不足一托识别尾板（包括拆零后不满一箱）；部分 SKU 托含量尚缺，不能用任意默认值补齐。
3. 使用按仓库、货主及 SKU 匹配的周转等级形成层级偏好；等级按近30天入库箱数＋出库箱数计算，详见 7.3；与尾板冲突时尾板优先。具体层级及混放优先口径见5.4，ABC分类采用累计贡献80%/95%。
4. 按单库位单托盘约束筛选可用库位；混放候选按确认后的规则处理。
5. 在满足约束和优先规则的候选方案中优化入库距离。
6. 输出推荐方案、距离及未能分配的货物与原因。

### 5.3 输出

- 推荐库位、货架、层及 SKU 数量明细，不要求托盘编号。
- 整托/尾板标识、周转等级；存在混放时展示各 SKU 明细。
- 推荐方案的距离统计，按确认后的口径计算。
- 无法分配、输入缺失及优先规则未满足的说明。
- 推荐后的预计库存状态；实际作业后默认外部库存已更新，下次调用仍须重新查询实时库存快照。

### 5.4 当前入库操作规则

- 入库推荐只安排本次新到货物，不主动搬动已有库存，不通过合并已有托盘、下移、上移、交换或临时中转腾位。
- 先满足尾板和周转等级的层级偏好，再优化入库距离；第1层不放普通整托，拆零后不足一箱优先，其次为其他不足一托货物。未混托尾板在第1层不足时允许上高层；高层不放混托。
- 入库允许两种混托方式：将本次新入库的不足托货物追加到第1层已有货物所在托盘；将本次新入库的多个SKU组混托，放入同一个第1层空货位。两种方式均不搬动已有货物所在位置。按最新出库讨论补充：已形成的混托不再追加货物；追加目标须排除已有混托。
- 同货主所有SKU可混放，不允许跨货主；容量暂取所有参与混放货品（包括已有库存）的最小托含量，已有数量与新增数量合计不得超过该容量。各货品原有入库时间及本次新货入库时间分别保留。
- 混放方案在Web页面明确对应SKU及货位，可提示：`{sku编码-sku名称}在货位{货位号}混合存放`。
- 非尾板层级偏好保持：高周转优先第2层，中周转第2—4层为软偏好，低周转优先最高层；无等级默认最低等级。ABC分类不作为货位配额，分配须检查实际托数及各层容量；ABC采用累计贡献80%/95%；偏好层不足时，在满足货主、容量及存放限制的其他合法候选货位中按距离退让，不另设固定层级顺序。第1层不放普通整托、高层不放混托等限制不因距离退让而解除。
- 在上述规则下货位不足时，Web弹出提醒：`库位不足，需要移库`。入库流程不得直接执行移库；仅在用户明确同意后触发独立移库功能。移库功能另行讨论，本轮不确定具体移库动作、执行方式或规则，也不代表已实现。

### 5.5 独立移库功能边界（后续讨论）

高层尾板下移、已有尾板合并、层级调整、交换和临时中转等涉及搬动已有库存的动作，统一从当前入库推荐中移出，留待独立移库功能讨论。此前列举的场景不作为入库时自动执行的规则，也不沿用“第1层无空位先合并已有尾板”的自动操作顺序。

入库不足时先提醒并取得用户同意，再触发移库功能。具体移库方案、执行确认、结果回传及移库后如何恢复入库推荐，留待该功能单独讨论。规格或货位状态变化由用户手动调整的既有约定保持。

## 6. 出库拣货路径推荐

### 6.1 输入

- 出库订单或任务：SKU、需求数量、货主及关联单号；当前不考虑指定批次，批次按入库时间理解。
- 每次调用先查询实时库存快照，包含库位、SKU 数量、拆零/尾板状态及入库时间明细，不要求托盘编号。
- 出库模式：一单一趟或波次合并，通过 storeBatchFlag 传递；1为按波次、0为按单；默认值及波次请求边界待确认。
- 可通行通道网络、库位对应的取货停靠点；作业起点与出口均采用 C14、C15 货架外 3.5 米处的同一备货区。
- 一托容量的判定资料：各 SKU 的标准每托箱数及箱内单位换算。不同 SKU 合拣时，按该托所含 SKU 中最少的标准每托箱数作为一托容量上限，所有 SKU 的取货数量统一换算为箱后累计。
- 求解器、时间限制和线程数。

### 6.2 流程与功能

1. 检查订单、库存和通道数据。
2. 根据需求选择库存，优先清空尾板，多个尾板按入库时间 FIFO 选择，同一入库时间时优先距离近的货位。需求小于最早尾板余量时允许部分取；需求超过其余量时先取尾板再拆零。尾板库存不足时，整托之间也按入库时间选择。
3. 库存不足时输出可满足部分，并明确报告未满足的SKU和数量；Web弹窗提醒缺货，平台响应须提供结构化缺货字段，见6.4。不能输出表面完整的方案。
4. 根据选定库存形成拣货明细，在叉车最多承载一托的约束下优化作业路线。未满一托且仍有待拣货物时继续拣货；拣满一托即送到出口，卸货后继续剩余拣货任务。最后不足一托的货物也送至出口。
5. 输出路径、距离、逐库位/SKU 取货量和拣货后的预计剩余库存。

FIFO 只限制选择哪些库存及各取多少，不限制路线访问顺序。选定的较晚入库库存可以先访问，但不得为了缩短距离而改选库存、绕过尾板优先或入库时间 FIFO。

出库距离为完整作业路线各段距离之和，包括起点至首个拣货点、拣货点之间、满托送往出口、出口返回后续拣货点，以及最后一批货物送到出口的距离。上述各段沿用水平通道实际距离加加权层间距离的统一口径。“一单一趟”表示按单组织任务；单个订单超过一托时仍须分多次送出口，不能解释为不受容量限制的一次搬运。波次合并也遵守同一容量规则。

已确认所有货位作业点均位于该货位第1层外侧的通道处；同一竖向位置不同层的货位映射到对应的地面作业点，保留各层取货明细。层间距离为1.7米，层间距离权重初始值仍待确认。同一点不同层的任务如何合并展示后续梳理。模型不引入设备升降时间。

不同 SKU 合拣的容量先采用简化口径：一托容量（箱）= 该托所含各 SKU 标准每托箱数的最小值，累计箱数不得超过该值。例如 A 为 40 箱/托、B 为 60 箱/托，A、B 合拣一托时最多共装 40 箱。入库库位混放现阶段也采用最小托含量的临时容量口径，见 7.4；两者均须遵守货主隔离要求。

### 6.3 输出

- 拣货任务：订单/任务、SKU、库位、层、入库时间明细、取货数量。
- 路线：起点、出口、停靠点访问顺序、各次送出口的分段路线、取货量及载货量变化、实际通道路径、分段距离和总距离。
- 预计清空的拆零托盘及剩余库存明细。
- 未满足需求及原因。

### 6.4 本轮出库确认及待澄清事项

- `storeBatchFlag=1`为按波次，`storeBatchFlag=0`为按单。按单请求保证来自同一货主；波次不拆分为多个波次。波次含多个货主时，每次载货仅允许同一货主，必须先送出口卸货，再切换货主；即使当前未满托也不得跨货主混载。波次内保留订单及货主明细，不跨货主替代库存。
- 当前不考虑指定批次；业务批次按入库时间理解，不新增指定批次内FIFO规则。
- 缺货时返回可满足部分，并提示缺货。Web采用弹窗；平台响应需要结构化缺货字段。建议字段 `shortages` 为数组，每项包含 `order_no`（关联单号）、`owner_code`、`sku_code`、`sku_name`、`requested_quantity`、`fulfilled_quantity`、`shortage_quantity`、`unit`；无缺货时为空数组。字段名、数量单位及响应包装待平台联调确认，不以message替代可解析的缺货明细；波次仍保留订单缺货归属。
- 一托含多个SKU时，当前不判断其是否达到满托；混托存放第1层，形成后不再追加货物。该限制同步适用于后续入库；混托部分出库后仅剩一个SKU时的追加资格，以及混托状态如何识别，仍待确认。
- 单SKU尾板继续优先出库，多个尾板按入库时间FIFO；同时间优先距离近的。不能假定同一货主同一SKU永远只有一个尾板，模型须支持多个来源货位及时间明细。
- 合拣过程中，加入下一SKU后容量可能因最小托含量降低。以加入后所含SKU的最小托含量校验累计箱数：若会超过新上限，先将当前货物送出口卸货，再拣下一SKU；若恰好达到新上限，先拣完本次取货量，再送出口卸货。不得先超载再返回出口；容量检查和货主隔离同时成立。
- 本轮仅更新需求，未修改入出库算法或平台响应实现。

## 7. 输入资料与数据准备

用户将提供货位布局图、SKU 主数据信息和主入库历史数据，资料形式为文档。应先核对资料内容，再整理为框架可读取的数据表。当前不承诺自动解析任意文档或图纸；识别出的字段、单位及对应关系需核实。

| 资料                               | 需提取/核实的信息                                                        | 用途                             |

### 7.3 按货主区分的周转等级

- 阈值分析对比两个口径：仅出库箱数，以及入库箱数＋出库箱数。后者已确认采用相加，表示总搬运箱数，不做相减；按同一连续30天窗口、仓库＋货主＋SKU分别统计，并在同仓库内比较。现已选定入库箱数＋出库箱数为正式分类指标，累计贡献阈值为80%/95%；仅出库口径保留作分析对照。
- 正式指标为入库箱数＋出库箱数，即总搬运箱数，用于周转等级划分，不是出库量除以平均库存的财务周转率。箱数＝主单位数量÷转换率，1件＝1箱，保留拆零小数。
- 滚动最近30天，包含截止日；初始样例使用 `data/slotting/orders.csv`，以最新出入库作业日期为截止日。上传完整订单历史时可指定截止日，默认当天。
- 按仓库编码＋货主编码＋货品编码分别累计；货主编码必填。同 SKU 不同货主不合并数量。
- 在同一仓库内，将各货主＋SKU作为独立条目统一按箱数降序排名；同量先按SKU编码、再按货主编码升序，后者仅用于原有排序条件完全相同时稳定排名。
- ABC正式规则：按总搬运箱数降序累计，A（高）覆盖前80%，B（中）继续覆盖至95%，其余为C（低）。跨越阈值的边界条目纳入较高等级，同量条目整组保留，故实际累计占比可超过阈值；与已给出的分析方案一致。不再按条目数三等分，等级也不代表固定货位配额。仅窗口内有出入库记录的条目进入统计，零总搬运量为最低等级，无等级货品在入库规则中默认最低等级。无任务日按0处理，统计连续30个自然日。当前正式计算代码仍为旧口径，本轮仅确认并更新需求文档，尚未切换实现。
- 支持手动更新，每次使用本次完整文件重算，不累加之前上传、不自动去重。输入及结果按次保存；周期更新频率后续确定。等级在货位规划中的使用尚未接入。

## 8. 框架与页面要求

沿用当前技术架构，不在需求讨论阶段新增不必要抽象：

- data/：按业务组织输入数据，支持手动选择/上传输入。
- modules/：入库与出库业务预处理、建模、服务和结果整理。
- solvers/：启发式、COPT、OR-Tools 后端；沿用项目三种方式的要求。现有拣货基线只有启发式和 OR-Tools，立体库的 COPT 后端需要后续补充，不能标记为已有能力。
- apps/：FastAPI 页面、任务调度与结果展示。
- results/：每次求解的输入记录、参数、状态、结果和距离统计按任务保存。
- doc/：需求与业务口径说明。

入库推荐和出库路径分别提供配置与结果展示页面；支持求解器选择、时间限制和线程数设置。各后端参数支持差异应如实展示。

结果页面需能区分货架层并查看库位/SKU/入库时间明细；展示路线和距离。采用分层二维图还是三维图后续确认，不默认三维是必需功能。

求解结果保存与实际库存变更分开处理。作业后默认外部库存已更新；每次调用出入库算法前均先查询实时库存快照，避免库管未按推荐执行导致下次计算沿用错误库存。推荐后的预计库存不能替代下一次查询，也不表示本项目已实现库存自动回写。当前入库不主动移位；货位不足时提醒用户，同意后触发独立移库功能，具体规则另行讨论。

### 9.1 Q-02：已确认的入库距离口径

入库只优化本次入库距离，暂不考虑未来出库成本。按入库口到各推荐库位的逐托单程距离累计，不计返程。例如两托分别送到距离入口 10 米和 20 米的库位，统计为 30 米。托数是搬运数量，不要求托盘编号或逐托决策变量。

出库则按每次最多一托、满托送出口再继续拣货的完整路线统计，与入库单程累计口径分别处理。

### 9.2 Q-10：已确认的 FIFO 与整托选择规则

FIFO 约束库存选择，不限制路线访问顺序。例如较早入库的 A 和较晚入库的 B 都已按需求选定，路线可以先到 B 再到 A，但各处取货数量仍须符合已确定的 FIFO 分配。

优先使用尾板后仍有需求时，整托也按入库时间选择。例如 A 整托入库较早但较远，B 整托入库较晚但较近，应先选择 A，不能为了缩短路线改选 B。

## 10. 验收场景

下列验收基于已确认规则；涉及待确认项的期望结果，应在业务口径确定后补齐。

| 场景 | 验收要点 |
| --- | --- |
| 货主隔离 | 入库不得跨货主混放；出库不得将不同货主的货位混发；相同 SKU 不能用其他货主的库存补足需求 |
| 周转统计按货主区分 | 同仓库同 SKU 的不同货主分别累计入库＋出库箱数，结果保留仓库、货主及 SKU 编码，不合并跨货主数量 |
| SKU必要主数据缺失 | 入库先查询平台最新规格；仍缺时Web弹窗、平台调用失败并返回7.4约定message，失败码待确认 |
| 连续30天历史 | 无出库任务的日期计0，不改成30个有记录日 |
| 双向通道与拣货点 | 实际交叉连接处连通；作业点在对应第1层外侧通道，层间距离1.7米 |
| 入库混放临时容量 | 同货主A为40箱/托、B为60箱/托时，混放累计不超过40箱 |
| 空位入库 | 推荐合法库位，不超过一托容量，层号和距离可核查 |
| 已占用库位 | 仅可将新增不足托货物追加到同货主第1层托盘，容量按已有及新增全部货品校验；不得放第二个物理托盘或移动已有库存 |
| 入库货位不足 | Web弹出“库位不足，需要移库”；未经用户明确同意不得触发独立移库功能 |
| 尾板入库 | 在可满足时体现 1 层优先；不足时执行确认后的处理规则 |
| 高/低周转入库 | 在可满足时体现对应层级偏好；冲突按确认后的优先级处理 |
| 不足一托的不同 SKU | 允许满足混放条件的方案，同时校验实际托盘容量；整托不能因该规则混放 |
| 多个拆零托盘出库 | 优先清空拆零托盘，按入库时间 FIFO 选择，数量守恒；FIFO 不限制路线访问顺序 |
| 尾板定义 | 不满一托均识别为尾板，包括拆零后不满一箱，统一适用尾板优先规则 |
| 整托 FIFO | 尾板库存不足时按入库时间选择整托，不因距离近改选较新库存 |
| 叉车容量与路线 | 每次最多一托，未满且有任务时继续拣；满托送出口后继续，最后不足一托也送出口；各段距离之和等于总距离 |
| 入库目标与距离 | 仅优化本次入库距离，不引入未来出库成本；逐托累计单程距离，不计返程 |
| 默认布局尺寸与备货区 | 货位长 1.15 米、深 1.125 米，过道宽按 3.5 米；入库起点和出库起终点共用 C14、C15 货架外 3.5 米处、宽为两货架宽度之和的备货区；按大致区域展示，不要求精确坐标 |
| 不同 SKU 合拣容量 | A 为 40 箱/托、B 为 60 箱/托时，A、B 合拣一托累计不超过 40 箱；不能按 60 箱或按比例折算放宽 |
| 尾板部分取货 | 小于最早尾板余量时允许部分取；超过时先取尾板再拆零，不超取 |
| 出库两种模式 | storeBatchFlag=0按单、=1按波次；波次不拆，每次载货仅同货主，切换货主前必须到出口卸货 |
| 合拣新容量超限 | 当前载货30箱、容量60箱，下一SKU容量40箱且本次拟取15箱时，先卸当前30箱再拣15箱，不形成45箱载货 |
| 合拣恰好满载 | 当前载货30箱、容量60箱，下一SKU容量40箱且本次取10箱时，拣完形成40箱后送出口卸货 |
| 部分缺货 | 输出可满足部分，Web弹窗，平台结构化缺货明细保留订单、货主、SKU、缺货数量及单位 |
| 混托不追加 | 不按是否满托判定追加资格；已形成的混托保持第1层且不再追加 |
| FIFO同时间 | 同货主同SKU在尾板优先及FIFO同级条件下，优先距离近的货位 |
| 实时库存 | 每次调用先查询实时快照；外部实际执行与上次推荐不同时，以新快照为准 |
| 无托盘编号 | 按货物—货位及入库时间明细完成容量校验和 FIFO，不依赖托盘编号 |
| 混托部分出库 | 只扣减对应 SKU 数量，不误清空其他 SKU；整托物理清空需所有货物取完 |
| 通道绕行/不可达 | 路线沿可通行网络计算；不可达时明确报告，不穿越货架 |
| 库存/容量不足 | 输出未满足数量与原因，不伪造完整可行结果 |
| 手动选择与求解参数 | 两个功能均支持输入选择和规定后端/参数；结果可追溯到输入与参数 |
| 多次求解 | 任务结果独立保存，不覆盖之前的任务 |

“最小化距离”是优化目标，不能把限时启发式或未证明最优的求解结果称为全局最优。结果应区分可行解、最优解、未找到可行解及失败，并保留后端可提供的状态信息。

# 前后端分层与统一仓储入口

入库、出库相关的新请求统一由 `apps/warehouse_service.py` 接收。Web页面和远程平台共用同一个入库POST、同一个出库POST；任务区分由这两个接口完成，不按请求来源建立第二套算法接口。

## 目录职责

| 文件或目录 | 职责 |
| --- | --- |
| apps/web_portal.py | 服务启动、页面、静态资源和路由装配 |
| apps/warehouse_service.py | 仓储HTTP接口、平台数据获取调用边界、公共校验协调、任务分发、结果保存与读取 |
| apps/warehouse_data.py | CSV/XLSX解析、SKU规格读取、字段标准化、数量换算及共用库存校验；不依赖FastAPI |
| modules/slotting/planning_service.py | 立体库入库任务流程：周转等级准备及入库算法调度 |
| modules/picking_path/planning_service.py | 立体库出库任务流程：按单/波次模式校验及出库算法调度 |
| modules/slotting/input_service.py、modules/picking_path/input_service.py | 任务方向的薄包装，分别筛选入库、出库订单；调用共用数据处理 |
| solvers/warehouse_inbound_heuristic.py | 入库启发式 |
| solvers/warehouse_outbound_heuristic.py | 出库启发式，包括FIFO库存选择与容量路径规划 |
| core/warehouse_layout.py | 共用货位布局、通道图和最短路径 |
| apps/static/ | 页面、数据上传及结果展示 |

原 `apps/slotting_api.py`、`apps/picking_path_api.py`、`apps/warehouse_planning_api.py` 合并至统一入口；原 `modules/warehouse_service.py` 拆入统一入口、共用数据文件及任务目录；原 `core/warehouse_inputs.py` 的解析代码迁入 `apps/warehouse_data.py`。不保留同名旧实现。

原 `modules/*/service.py`、`apps/web_api.py` 为已有基线模型与旧任务接口，本次不改其行为；新立体库页面使用统一仓储入口。

## 调用链

```text
Web页面 / 远程平台
    → apps/warehouse_service.py：入库POST / 出库POST
        → 文件模式：使用本次加载的数据
        → 平台模式：get_inventory_snapshot / get_sku_master_data
        → apps/warehouse_data.py：标准化与共用校验
        → modules/slotting 或 modules/picking_path：任务流程
        → solvers：算法
        → 统一保存及返回结果
```

平台提供的两个GET由后端主动调用，不额外冒充本项目对外GET接口。调用函数集中在 `apps/warehouse_service.py`：

- `get_inventory_snapshot(request)`：取得并标准化本次库存。
- `get_sku_master_data(sku_ids, request)`：取得并标准化SKU规格；request携带货主、仓库等上下文。

远程地址、鉴权、请求字段及响应映射仍待联调。当前函数明确返回未接入错误，不发送猜测协议的请求，不退回本地样例。

## 对外接口

现有页面地址保持兼容：

- `POST /api/slotting/plan`：入库规划。
- `POST /api/picking-path/plan`：出库规划。
- `GET /api/{module}/inputs/{kind}/sample`：样例加载。
- `POST /api/{module}/inputs/{kind}`：CSV/XLSX上传。
- `POST /api/warehouse/specs`：规格上传。
- `GET /api/warehouse/runs/{run_id}`：读取结果。
- `/warehouse-results/{run_id}`：独立结果页面。

module只接受slotting、picking-path；kind接受inventory、orders。入库样例订单筛选2026-09-22，出库样例订单筛选2026-09-09（当前可用库存满足当天全部出库需求），上传订单按任务类型筛选且不限制日期。

规划请求 `source` 缺省为 `file_snapshot`，使用本次传入的库存、订单及可选规格。`source=platform` 使用同一个POST入口，每次重新调用平台库存和规格函数，覆盖调用方传入的旧库存/规格；订单仍由请求提供。目前该分支仅建立待联调调用边界，尚非平台正式协议。

结果继续按次保存于 `results/warehouse/{run_id}/`，包含输入快照、设置及结果。规划不会回写外部库存，推荐后预计库存不作为下一次请求的真实快照。

算法设置、周转更新及旧演示任务接口保持各自已有职责。登录和平台鉴权没有在本次整理中新增。
